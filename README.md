# Форма — дизайн интерьера и предметные композиции

Самостоятельный редактируемый сайт: `index.html` и локальные `assets/`. Актуальная версия сохраняет композицию, шрифты и пространственную прокрутку; тексты и форма обновлены по запросу владельца.

Pages: https://sadikovsa.github.io/interior-light-v2/ — существующий адрес. Новую редакцию root проверяет после публикации; прежнее подтверждение не доказывает новую загрузку.

## Редактирование и сборка

Изменяйте исходники в корне пакета, затем выполните `python3 build.py`. `dist/` содержит только производный публичный сайт. Python использует стандартную библиотеку, установка зависимостей и сетевые запросы для сборки не нужны. Main хранит редактируемый пакет; gh-pages — только содержимое dist с .nojekyll в корне.

Локальный просмотр: `python3 -m http.server 4173 --bind 127.0.0.1 --directory dist`; откройте http://127.0.0.1:4173/ и завершите сервер после просмотра.

## Описание задачи

Форма готовит редактируемый текст. «Скопировать» и «Сохранить TXT» используют текущие правки; при недоступном clipboard можно выделить текст вручную. Отправка и автоматическое сохранение отсутствуют. Изменение исходных полей скрывает прежний результат до повторной подготовки.

## Контроль изменений

SOURCE-CHECKPOINT и SOURCE-INVENTORY различают исторический исходник, текущую редакцию и публикацию. PACKAGING-CHECKS/BUILD-INVENTORY содержат актуальные hashes и статические проверки. Исторические body/source hashes и отчёты сохранены в history. После этой редакции body, некоторые текстовые SVG, interface JS/CSS и manifest изменены: прежнее byte-identical утверждение относится к первому переносу. Photos/fonts/vendor/main.js/architecture geometry не менялись. Provenance и исторический контекст остаются в исходных ledger/.studio/history и не входят в dist. DESIGN.md описывает исходный дизайн; это не повторное художественное утверждение.

noindex,follow сохранён. Метаданные не выдумывают клиентов, реализованные объекты, юридические сведения или контакты. Native Tunnel/Zoom-through, reduced-motion и noJS сохраняют прежний контракт; текущие пользовательские изменения требуют focused QA и проверки нового deployment.
